# 检查更新与一键更新

入口：**设置 → 软件更新**。

本功能从 `wusuiling-if/ai-virtual-phone` 的 `codex/phone-compatibility` 分支检查更新，并把新提交快进同步到本站实际部署的 `main` 或 `codex/phone-compatibility` 分支。不是从原作者仓库拉取代码。2026-09-16 添加。

**Vercel 命令行部署的站点**不会在推送 GitHub 后自动重新发布。部署电脑先拉取 `main`（或兼容分支）并提交本地修改，再运行 `npm run deploy:vercel`；此命令要求工作区干净，并将当前 Git 提交号写入构建，供站内版本检查使用。此前用普通 `vercel deploy` 且上传时排除了 `.git` 的版本可能显示“未记录构建版本”。如需站内一键更新，请把自己的 Fork 连接到 Vercel 的 Git 自动部署，并把生产分支设为 `main` 或兼容分支。

## 第一次启用

旧网站没有这个入口，需要先手动同步并部署包含本功能的版本一次。以后可从小手机里操作。

1. 在 GitHub Fork 本兼容版仓库。旧的原作者 Fork 不属于这个新的仓库网络，不能使用本功能。
2. 将自己的 Fork 连接到 Vercel / Netlify，生产分支选 `main`（已有兼容分支部署可继续使用 `codex/phone-compatibility`），开启 Git 自动部署。仅下载 ZIP 或自己搭建服务器、没有部署自动化的用户仍需自行部署。
3. 在“软件更新 → 首次配置 / 更新授权”填写自己的 `用户名/仓库名`。
4. 在 GitHub 创建 Fine-grained personal access token，仅选择这个仓库，授予 **Contents: Read and write**。若更新包含 `.github/workflows` 的变更，还需要 **Workflows: Read and write**。组织仓库可能需要管理员批准，受保护分支需按其规则更新。
5. 把令牌填入软件更新页。默认只保留在组件内存；勾选“在当前标签页会话中记住授权”才保存到 sessionStorage。关闭标签页、清除会话或令牌到期后需要重新输入。不保存到 IndexedDB、localStorage 或小手机备份；网络请求直接发往 `https://api.github.com`，本站服务器不接收此令牌。

GitHub 令牌能修改选定仓库，请只在自己的可信站点输入。不要使用模型 API Key，也不要把令牌提交到 GitHub。

## 日常更新

点击“检查更新”：

- **当前已是最新版本**：无需操作。
- **本站已部署新版本**：点击“载入新版”即可，不需要 GitHub 授权。
- **发现可更新版本**：点击“一键更新”。会确认更新来源、写入权限及分支关系，仅执行快进更新，并核对写入后的提交。
- **自定义分支 / 未知构建版本**：不会自动覆盖，需要手动检查与合并。

一键更新同步完成后，等待已连接的部署平台自动构建。页面每 15 秒读取本站版本，最长等待 10 分钟。确认所选提交已上线后，停留在前台的更新页面会在 5 秒后载入新版，可以点“稍后载入”取消。离开软件更新页或切到后台，不会强制刷新；之后可重新检查。

如果 10 分钟内未检测到所选版本上线，页面会提示查看部署日志。**同步代码成功不等于部署成功**。检查部署是否失败、是否选错生产分支、是否暂停自动部署。不要以为刷新浏览器能替服务器发布代码。

更新不会清除本地数据库、角色、聊天、配置、媒体或推送订阅。重新载入会中断本页正在进行的工作，因此先结束生成与编辑，并在重要更新前导出备份；网址保持不变。新版本自身涉及的数据迁移仍需单独测试。

## 本次 Vertex / Vercel 更新（2026-09-18）

本次更新会识别 Vertex 流式响应提前结束，避免将半截回复当作成功；限流、鉴权、网关或网络错误不再立即重复发起同一次生成；协议降级时保留 Vertex 凭据，并保留上游 Retry-After。服务端增加只含请求编号、耗时、字节数和错误类型的传输日志，不记录密钥或对话正文。

更新代码不会自动更换托管平台：Netlify 用户仍在 Netlify 上运行，若遇到平台转发超时，需要另外迁移部署。新增的 Vercel 配置和操作说明见 [Vercel 部署](./vercel-deployment.md)。网络线路本身的断连也不会因代码更新自动消失。

直接使用维护者网站的访问者，在维护者发布后点“检查更新 → 载入新版”即可；不需要配置自己的 GitHub 令牌。自己部署的用户仍需满足上面的 Fork、更新授权和 Git 自动部署条件。CLI 手动发布的站点需要维护者再次发布，单纯推送 GitHub 不会更新该站点。

## 构建版本识别

构建时优先读取 `PHONE_BUILD_SHA`、Vercel 的 `VERCEL_GIT_COMMIT_SHA`、Netlify 的 `COMMIT_REF`；其次使用 `git rev-parse HEAD`。必须是完整的 40 位提交 SHA。

仓库名称可从部署平台元数据自动填写，但仍可由用户修正。代码不自动选择或改动其他分支，不强推，不主动删除 GitHub 或本地数据。分支存在额外提交、令牌权限不足、GitHub 限流或同步竞态都会停下并提示。

目前不提供自建 OAuth 服务，首次更新需要上述限定仓库的令牌授权。版本提示使用短提交号和最近提交说明，尚未接入稳定版 Release 通道。更新实现经过模拟 API 测试；没有用他人的仓库／部署账户做真实端到端升级。

参考：[GitHub 更新分支引用](https://docs.github.com/en/rest/git/refs#update-a-reference)、[Vercel Git 自动部署](https://vercel.com/docs/git)。
